The Repeatability Checklist

If the person who knows how it's done is unavailable tomorrow, what breaks? Use this checklist to find where knowledge needs a system.

All resources

Original FISCH tool · Free to use internally · Not a formal audit

Look for the repeating friction.

Pick one process or role. Mark the statements that sound familiar. Be specific; “our onboarding” is too broad, while “how new reps qualify a handoff” is a useful starting point.

Which statements are true?

Three or more checks? That's not a diagnostic score, but it's a good reason to investigate the work before buying more content.

Define the useful move.

One task that keeps breaking:

Where does it happen?

What does a good attempt look like?

What makes it difficult today?

What could someone use in the moment? (example, checklist, prompt, practice, automation)

Now build something small.

Choose one support that will get used this week. Put it in the workflow, ask a manager to observe its use, and check the result after two weeks.

The test: Did the work get easier, faster, more consistent, or less dependent on one person's availability? Don't call it successful because a document was published.

Want help turning this into a working system? Tell me which step keeps breaking.

A real problem is a good place to start.
